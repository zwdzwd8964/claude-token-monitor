## 一、这是什么

**一个人、3.5 天造出主体、如今停在「计划态」的个人 AI-coding 运维平台。**

两个纪元，断层线清楚：

| | 纪元一 · tokmon | 纪元二 · Claude Mission Control |
|---|---|---|
| 北极星 | 「我 vibe coding 烧了多少 token / 多少钱」 | 「它在替我跑的时候，是在**推进 / 卡住 / 烧钱 / 乱改**，重要时刻主动找我」 |
| 宪章 | [NORTH_STAR.md](../NORTH_STAR.md) | [MISSION_CONTROL.md](../MISSION_CONTROL.md) |
| 形态 | CLI（watch / report / doctor） | 一个本地 Web 驾驶舱，9 个页面 |

**数据源的核心洞察**：Claude Code 自己会把每个会话的 transcript 写进 `~/.claude/projects/**/*.jsonl`，
每条 assistant 消息带完整 `usage`。所以**不需要代理、不需要 hook、不需要改配置**——纯本地只读解析就能拿到全部真相。
整个平台建在这一个发现上。

架构是三层：**监控（三支柱）→ 事件总线 → 通知 / 控制**。支柱之间零耦合，只在事件层汇合。

## 二、功能全景

### CLI（5 个命令）

| 命令 | 干什么 |
|---|---|
| `watch` | 实时盯盘 TUI，5s 轮询 |
| `report` | 按天 / 项目 / 模型 / 来源汇总 |
| `doctor` | **两半体检**：成本契约（`doctor.py`）+ 推断契约（`inference_doctor.py`） |
| `backtest` | 用 transcript 的**未来当真值**回测状态推断准确率，三把尺（strict / medium / lenient） |
| `serve` | 起本地驾驶舱（纯标准库 `http.server`，零依赖可离线） |

### Web 驾驶舱（9 个页面）

| 页面 | 支柱 / 层 | 内容 |
|---|---|---|
| `/tokens` | 成本 | KPI + 「vs 上一周期」自基线对比 + 预算设置 |
| `/processes` | 进程 | 进程 / 端口 / 连接 / cloudflared / 健康探测，纯只读 + 脱敏 |
| `/sessions` | 活动 | 每个会话 `WORKING / PROCESSING / AWAITING_USER / AMBIGUOUS_PENDING / UNKNOWN` + mini-timeline |
| `/notify` | 通知层 | Telegram 出站 + **推送/抑制双记 feed**（能看到「为什么没打扰你」） |
| `/control` | 控制层 | 远程批 permission、终止进程、释放端口、**steer 发指令**、**答 AskUserQuestion 选择题** |
| `/billing` | 第 4 数据源 | Anthropic / OpenAI 官方 usage API（Google 诚实标「不可得」） |
| `/doctor` `/backtest` | 信任基建 | 体检与回测的 Web 视图 |

### 三个真正的技术硬货

1. **`activity.py` 的 `classify_state`** —— 纯函数，从 transcript 尾部推断会话状态。
   **时钟用最后一条消息的 timestamp，绝不用文件 mtime**（实测 29 个会话 mtime 比末条消息新 >30min，
   用 mtime 会让 79h 没动的会话看着「刚活动过」）。回测准确率 **97.0% / 1343 个评估点**，
   最伤信任的「假完成 / 假在跑」各仅 1 例（≈0.15%）。
2. **`control.py` 的失败安全** —— 用 Claude Code 官方 `PermissionRequest` http hook 做远程审批。
   token 错 / 超时 / 异常 / 模式关 → **每一条非正常路径都 defer 回退本地弹窗**，绝不自动批准。
3. **`runner.py` 的 `canUseTool`** —— 2026-07 实测钉死：`claude -p` 结构上拿不到多选按钮
   （模型把选择题打成纯文本就结束回合），只有 Agent SDK 的 `canUseTool` 能拦下 `AskUserQuestion`、
   拿到结构化选项、把你的选择塞回会话。为此**有意破了「零依赖」原则**，记录在案。

## 三、侧批（本文的重点）

### ⭐ 1. 它真正的护城河不是功能，是「把诚实工具化」

绝大多数个人项目的「我很严谨」停留在形容词，这个项目把它变成了**可运行的命令**：

- `doctor` → 检查「我对数据格式的假设还成立吗」
- `inference_doctor` → 检查「我对**自己的推断**的假设还成立吗」
- `backtest` → 用时间旅行给推断打分，**97% 不是声称，是算出来的**

而且诚实是 **grep 得到**的，不是口号：`pricing.rates_for` 未知模型返回 `(0,0,False)` 而不是瞎估；
`Event.make` 在构造函数里就用 allow-list 把会话正文滤掉，**生产者想塞敏感内容都塞不进去**；
`classify_state` 久未返回时统一并列「长任务 / 等授权 / 会话已关闭」而不伪造 `PERMISSION_NEEDED`。

> **侧批**：这套东西的价值高于平台本身。如果有一天这个项目死了，值得带走的是这个范式——
> **对每一条载重假设，写一个能跑的校验器**。

### 🔴 2. 最刺眼的一条：以「诚实」为人格的系统，在它最核心的页面上默认对自己撒谎

`serve.py` 的 `/sessions` 页今天仍然是：

```html
<input type="checkbox" id="hideidle" checked> 隐藏空闲会话
```

而 [SESSIONS_V3_PLAN.md](../SESSIONS_V3_PLAN.md) 的审计算得清清楚楚：160 个会话里 71 个「等你」，
其中 **70 个**被这个默认勾选删掉——**「谁在等我」这个这一页唯一存在的理由，被藏掉了 71 分之 70。**

更糟的是「空闲」这个词**语义是反的**：它实际意思是
「Claude 已经回复了你、超过 10 分钟没人接话」= **你欠 Claude 一句话**，不是「它闲着没事」。

> **侧批**：这违反的是项目自己的原则 1（真实优先）和 P6（误报零容忍）——而且是**在离用户最近的那一层**。
> 内核干净得像手术室，UI 却在默认状态下做减法。这条暴露了一个结构性偏科：
> **纪律全部投在「数据对不对」，几乎没投在「你看到的东西对不对」。**

### 📐 3. 设计通胀：1164 行的设计文档，0 行实现

| 文档 | 体量 | 状态 |
|---|---|---|
| `SESSIONS_FILTER_PLAN.md`（V1） | 162 行 | ✅ 已交付 |
| `SESSIONS_FILTER_V2_PLAN.md` | 196 行 | ❌ **写了从未实施** |
| `SESSIONS_V3_PLAN.md` | **1164 行** | ❌ 取代 V2，**仍未实施** |

V3 文档自己诚实写着：「V2 不是『上一版实现』，它是『一份没落地的诊断』」——然后 V3 重蹈覆辙，体量翻了 6 倍。

全仓体量：**文档 3793 行 / 代码 6676 行 / 测试 1566 行**。**文档是测试的 2.4 倍。**
7 月以来 5 份计划文档 2000+ 行，代码只动了 `runner` / `billing` / `serve`。

> **侧批**：V3 的分析质量极高（F7–F12、`|| 0` 让「未知」冒充 1970 年浮到第一行伪装成「最该看的那个」——
> 这种细节是真本事）。但**分析质量越高，不实施的浪费越大**。而它要修的核心 bug，是一个 `checked` 属性。
> **1164 行设计挡在 10 行修复前面**，这是最贵的完美主义税。

### 🔓 4. 唯一会真的伤人的债：读页零鉴权

`_ctl_guard` 只护控制端点。`/sessions` `/tokens` `/processes` `/api/*` **至今没有任何鉴权**
（`grep MC_REMOTE tokmon/` 零命中）。`MC_REMOTE`（读页也要 token）在
[REMOTE_CONTROL_PLAN.md](../REMOTE_CONTROL_PLAN.md) §6 设计了，从未实施。

而这台机器**真的起过 cloudflared 公网隧道**（V2 §6 发现，PID 100908 → `127.0.0.1:8794`，2026-07-14 kill）。
裸奔期间，拿到 URL 的人能看到全部**会话标题、当前步骤、思考片段、花费**。
三份文档（V2、V3、`RUNNER_SDK_PLAN` §10）都用红字标了这条，**全都没做**。

> **侧批**：控制面的安全做得很讲究——`secrets.compare_digest` 常量时间比较、token 0600 原子写不回显、
> `_host_ok` 挡 DNS rebinding、令牌只在终端打印不经 HTTP 下发。**防御思维是在线的，只是漏在了「读」
> 这个被默认为无害的动词上。** 而这个平台读到的恰恰是最私密的东西：你在想什么、你在改什么、你花了多少钱。
> 隧道现在是关的，所以这条是「睡着的雷」——**下次谁顺手再起一次隧道，洞原样回来。**

### 🧭 5. 北极星漂移：从「我烧了多少钱」到「舰队远程驾驶舱」

三次原则破例，每次都有白纸黑字的理由（这点比 99% 的项目好）：

1. 「绝不干预」→「**从不*自动*干预**，只有你显式、经审计地干预」（M4 控制层）
2. 「不调计费 API」→「不爬 console，但可调**官方** usage API」（`/billing`，第二个受控破例出站）
3. 「零额外依赖」→ 引入 `claude-agent-sdk`（换「真·多选按钮」这个硬需求）

但累积效应是：**tokmon 的原初待办被跳过了**。`NORTH_STAR` §6 写着
「`report --by/--json` ← **下一个待做**」——至今 `report` 只有 `--since`。
项目从「打磨 report」一步跨进了整个平台。而 `NORTH_STAR` §10 给未来自己的话是：

> 「别把它做成一个炫的 dashboard 集合。」

今天是 **9 个页面的 dashboard 集合**。

> **侧批**：这不是失败——痛点是真的（手机答不了选择题确实卡人），每次拓宽都是**显式选择**而不是滑过去，
> 这正是 `MISSION_CONTROL` §9 要求的。但这句自我告诫现在应该**重新标定**，而不是继续挂在墙上当反讽。

### 🧱 6. 唯一的架构腐化点：serve.py 1958 行

内核的 P4 纪律是真守住了（import 图实测干净：`events.py` 只依赖 stdlib、`procmon` 零 pillar 耦合、
`billing` 绝不 import 成本内核）。**但外壳在长脂肪**：9 个页面的 HTML / CSS / JS 全部内联在一个文件里，
`table { width:100%; border-collapse:collapse; }` 这一条在 **563 / 915 / 1442 / 1552 / 1851 行各写了一遍**。

叠加测试分布：**130 passed in 0.64s**（很健康），但覆盖集中在纯函数
（`classify_state` / `decide` / `pricing` / `anth_amount_usd`），**`serve.py` 的 1958 行几乎零覆盖**，
前端 JS 完全没有。

> **侧批**：这两件事是同一件事的两面——**腐化的地方恰好是没测的地方，也恰好是 bug 所在的地方**
> （`hideidle` 就是前端 JS）。「测试全绿」和「用户看到的东西对」之间，有 1958 行的真空。

### ⚡ 7. 「左绿右红」：三个月了，手机环一次都没闭过

`EVOLUTION.md` 的结论现在仍然成立，而且更刺眼了：

```
观测 / 度量 / 信任  ━━━━━  通知 / 控制（外发与入站）
Gen0.1 内核    🟢      M3 通知     🔴 外发未验证
Gen0.3 doctor  🟢      M3.5 预算   🔴 送达未验证
M1 活动        🟢      M4 控制     🔴 远程审批未真机验证
M4.5 信任加固  🟢      M4.5(b)     ❌ Pushover 根本没写
```

核过代码：`grep -i pushover tokmon/` **零命中**（M4.5 敲定的「先用 Pushover 闭环」从未落地）；
Telegram **只有出站**，双向 `getUpdates` 只在 UI 帮助文字里出现过；隧道已关。

**所以「重要时刻主动找到我」——这个平台存在的全部理由——从 2026-06-27 到今天，一次都没在真实手机上兑现过。**

> **侧批**：这不是懒，是一个非常典型的**能力偏好陷阱**：作者擅长且享受「把判断做到可测量的 97%」，
> 而最后一公里是脏活（注册账号、配 token、忍受 push 的噪音、调打扰率）。
> 于是每次到了这一步，就诞生了一份新的计划文档。
> **S1-v2 的 steer 是这条红线上唯一被真正通电的一段**（A0 spike 实测 `canUseTool` 确实收到
> `AskUserQuestion`、答案塞回后会话带着选择继续跑）——它证明作者做得到，只是每次都先转向了别处。

### 📉 8. 文档熵：它自己就是它警告的那个病

`EVOLUTION` §4 把「文档对代码漂移」列为**元问题**。半年后，这个元问题恶化了：

| 项 | 现状 | 真实 |
|---|---|---|
| `__version__` | `"0.3.0"` | 实际已到 M4.5 + B1 + S1-v2 |
| git commit | `Initial commit: tokmon v0.3.0` | 同上，标签错了 |
| `CHANGELOG.md` | 停在 0.3.0 | 漂移 ~10 个切片 |
| `README.md` | 只提 `/tokens` `/processes` | **`sessions`/`notify`/`control`/`billing`/`backtest` 零次出现** |
| `EVOLUTION.md` | 「这不是 git 仓库」 | 8/2 已 git init |
| `docs/atlas.html` | 7/1 生成 | 不含 billing / steer / V3 |
| `requirements.txt` | 无 pytest | `EVOLUTION` §4 点名过，至今未修 |

> **侧批**：一个把「让漂移可被发现」当作头号风险管理手段的系统，**自己的文档漂移没有 doctor**。
> 最低成本的解法不是补文档，是**宣布单一真相源**。现在这 15 份文档互相引用、互相取代、部分已失效，
> **新来的人（包括未来的你、包括未来的 Claude session）读完会得到一张过期地图。**

### ⏸ 9. 节奏：它现在停在「计划态」

## 四、重启计划（已采纳，按杠杆 / 成本排序）

不按原路线图，按「什么最该先做」：

| # | 动作 | 成本 | 为什么是它 |
|---|---|---|---|
| **1** | **删掉 `/sessions` 那个默认 `checked`** | 10 分钟 | 全仓性价比最高的一次修改。不吞 V3 的 1164 行设计，先把 70/71 的谎话停掉 |
| **2** | **补 `MC_REMOTE` 读页鉴权** | 半天 | 唯一会真的伤人的债，且是「上手机」的硬前置 |
| **3** | **闭一次手机环**（Pushover 单向出站起步） | 一天 | 三个月没兑现过的核心承诺，所有材料已备好 |
| **4** | **文档降熵**：定单一真相源、版本号对齐、README 重写 | 半天 | 让下一个接手的人拿到的是地图而不是考古层 |

前三件约 2 天，能让这个系统**第一次真正开始履职**。
