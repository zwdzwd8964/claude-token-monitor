01这是什么

两个纪元，断层线清楚。

纪元一 · tokmon纪元二 · Mission Control
北极星 我 vibe coding 烧了多少 token / 多少钱 它在替我跑时，是在推进 / 卡住 / 烧钱 / 乱改，重要时刻主动找我
宪章NORTH_STAR.mdMISSION_CONTROL.md
形态CLI（watch / report / doctor）本地 Web 驾驶舱，9 个页面

数据源的核心洞察：Claude Code 自己会把每个会话的 transcript 写进 ~/.claude/projects/**/*.jsonl，每条 assistant 消息带完整 usage。 所以不需要代理、不需要 hook、不需要改配置——纯本地只读解析就能拿到全部真相。 整个平台建在这一个发现上。

┌ Layer 1 监控层  成本(tokmon) · 进程(procmon) · 对话活动(activity)   三支柱互不引用
│                                    ↓ raw signals
├ Layer 2 事件总线  有类型的事件 + 严重度 + payload allow-list        支柱只往这里发
│                                    ↓ typed events
└ Layer 3 通知 / 控制  该不该打扰你 · 怎么打扰 · 你显式下达的指令      唯一的出站与入站

三个真正的技术硬货

模块硬在哪
activity.py
classify_state		 纯函数，从 transcript 尾部推断状态。时钟用最后一条消息的 timestamp，绝不用 mtime （实测 29 个会话 mtime 比末条消息新 >30min）。回测 97.0% / 1343 个评估点， 最伤信任的「假完成 / 假在跑」各仅 1 例。
control.py
失败安全		 用官方 PermissionRequest http hook 做远程审批。token 错 / 超时 / 异常 / 模式关 → 每一条非正常路径都 defer 回退本地弹窗，绝不自动批准。
runner.py
canUseTool		 实测钉死：claude -p 结构上拿不到多选按钮（模型把选择题打成纯文本就结束回合）。 只有 Agent SDK 的 canUseTool 能拦下 AskUserQuestion 并把你的选择塞回会话。 为此有意破了「零依赖」原则，记录在案。

03侧批

每一条都带可复核的坐标（文件:行号 / 实跑输出 / grep 结果）。

优势1 · 它真正的护城河不是功能，是「把诚实工具化」

绝大多数个人项目的「我很严谨」停留在形容词，这个项目把它变成了可运行的命令： doctor 检查「我对数据格式的假设还成立吗」、inference_doctor 检查「我对自己的推断的假设还成立吗」、 backtest 用时间旅行给推断打分——97% 不是声称，是算出来的。

而且诚实是 grep 得到的：未知模型返回 (0,0,False) 而不是瞎估； Event.make 在构造函数里就用 allow-list 把会话正文滤掉，生产者想塞敏感内容都塞不进去； 久未返回时统一并列「长任务 / 等授权 / 会话已关闭」而不伪造 PERMISSION_NEEDED。

侧批：这套东西的价值高于平台本身。如果有一天这个项目死了，值得带走的是这个范式—— 对每一条载重假设，写一个能跑的校验器。

最刺眼2 · 以「诚实」为人格的系统，在最核心的页面上默认对自己撒谎

serve.py 的 /sessions 页今天仍然是 <input type="checkbox" id="hideidle" checked> 隐藏空闲会话。

而 V3 审计算得清清楚楚：160 个会话里 71 个「等你」，其中 70 个被这个默认勾选删掉—— 「谁在等我」这个这一页唯一存在的理由，被藏掉了 71 分之 70。

更糟的是「空闲」这个词语义是反的：它实际意思是「Claude 已经回复了你、超过 10 分钟没人接话」 = 你欠 Claude 一句话，不是「它闲着没事」。

侧批：这违反的是项目自己的原则 1（真实优先）和 P6（误报零容忍）——而且是在离用户最近的那一层。 内核干净得像手术室，UI 却在默认状态下做减法。结构性偏科：纪律全部投在「数据对不对」，几乎没投在「你看到的东西对不对」。

文档体量状态

V3 自己诚实写着「V2 不是『上一版实现』，它是『一份没落地的诊断』」——然后重蹈覆辙，体量翻了 6 倍。 全仓：文档 3793 行 / 代码 6676 行 / 测试 1566 行。

侧批：V3 的分析质量极高（|| 0 让「未知」冒充 1970 年浮到第一行伪装成「最该看的那个」——这种细节是真本事）。 但分析质量越高，不实施的浪费越大。而它要修的核心 bug，是一个 checked 属性。 1164 行设计挡在 10 行修复前面，这是最贵的完美主义税。

安全4 · 唯一会真的伤人的债：读页零鉴权

_ctl_guard 只护控制端点。/sessions /tokens /processes /api/* 至今没有任何鉴权（grep MC_REMOTE tokmon/ 零命中）。

而这台机器真的起过 cloudflared 公网隧道（PID 100908 → 127.0.0.1:8794，2026-07-14 kill）。 裸奔期间，拿到 URL 的人能看到全部会话标题、当前步骤、思考片段、花费。三份文档都用红字标了这条，全都没做。

侧批：控制面的安全做得很讲究——常量时间比较、token 0600 原子写不回显、挡 DNS rebinding、令牌只在终端打印。 防御思维是在线的，只是漏在了「读」这个被默认为无害的动词上。 隧道现在是关的，所以这是「睡着的雷」——下次谁顺手再起一次隧道，洞原样回来。

方向5 · 北极星漂移：从「我烧了多少钱」到「舰队远程驾驶舱」

三次原则破例，每次都有白纸黑字的理由（这点比 99% 的项目好）：「绝不干预」→「从不自动干预」； 「不调计费 API」→「不爬 console，但可调官方 usage API」；「零额外依赖」→ 引入 claude-agent-sdk。

但累积效应是：tokmon 的原初待办被跳过了。NORTH_STAR §6 写着 「report --by/--json ← 下一个待做」——至今 report 只有 --since。 而 §10 给未来自己的话是「别把它做成一个炫的 dashboard 集合」——今天是 9 个页面的 dashboard 集合。

侧批：这不是失败——痛点是真的，每次拓宽都是显式选择而不是滑过去。 但这句自我告诫现在应该重新标定，而不是继续挂在墙上当反讽。

架构6 · 唯一的腐化点：serve.py 1958 行

内核的 P4 纪律是真守住了（events.py 只依赖 stdlib、procmon 零 pillar 耦合、 billing 绝不 import 成本内核）。但外壳在长脂肪：9 个页面的 HTML / CSS / JS 全部内联在一个文件里， table { width:100%; border-collapse:collapse; } 在 563 / 915 / 1442 / 1552 / 1851 行各写了一遍。

叠加测试分布：130 passed 很健康，但覆盖集中在纯函数，serve.py 的 1958 行几乎零覆盖，前端 JS 完全没有。

侧批：这两件事是同一件事的两面——腐化的地方恰好是没测的地方，也恰好是 bug 所在的地方 （hideidle 就是前端 JS）。「测试全绿」和「用户看到的东西对」之间，有 1958 行的真空。

兑现7 · 「左绿右红」：三个月了，手机环一次都没闭过

观测 / 度量 / 信任  ━━━━━  通知 / 控制（外发与入站）
Gen0.1 内核    🟢      M3 通知     🔴 外发未验证
Gen0.3 doctor  🟢      M3.5 预算   🔴 送达未验证
M1 活动        🟢      M4 控制     🔴 远程审批未真机验证
M4.5 信任加固  🟢      M4.5(b)     ❌ Pushover 根本没写

核过代码：grep -i pushover tokmon/ 零命中；Telegram 只有出站， 双向 getUpdates 只在 UI 帮助文字里出现过；隧道已关。

所以「重要时刻主动找到我」——这个平台存在的全部理由——从 2026-06-27 到今天，一次都没在真实手机上兑现过。

侧批：这不是懒，是典型的能力偏好陷阱：作者擅长且享受「把判断做到可测量的 97%」， 而最后一公里是脏活（注册账号、配 token、忍受噪音、调打扰率）。于是每次到了这一步，就诞生了一份新的计划文档。 S1-v2 的 steer 是这条红线上唯一被真正通电的一段——它证明作者做得到，只是每次都先转向了别处。

04重启计划（已采纳）

不按原路线图，按「什么最该先做」——杠杆 / 成本排序。
