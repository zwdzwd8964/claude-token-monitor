概览 · Overview

平台总览 总览 · 概念层

Claude Mission Control 是一个「AI coding 运维驾驶舱」。它从一个纯粹的 token 成本工具（tokmon） 长成了统管三个只读支柱（成本 / 进程 / 活动）的平台，脊柱是单向的三层数据流： 监控层 → 事件总线 → 通知层，外加一条旁路控制层与一层推断校验（doctor）。 整座塔只做两件事：看清它在推进 / 卡住 / 烧钱 / 乱改，并只在重要时刻恰当地提醒你。

五个组成部分

监控层 · 三支柱

成本（tokmon）/ 进程（procmon）/ 活动（activity）三个互不引用的只读内核，各自产出「原始信号」。

事件总线

events.py 把信号判成带严重度的有类型事件。它 import 任何支柱都不允许——解耦的关键。

通知层

notify.py 只做一件事：决定该不该打扰、怎么打扰。默认静默、默认不外发。

控制层（旁路）

control.py 是唯一能「动手」的层，但永不自动——只执行你显式下达、经 P7 护栏的 permission 审批。

推断 doctor

给 activity / events 这些推断层一把「对真相」的尺，让它们像成本（测量）一样敢信。

🧭
平台北极星：「当 Claude Code 在替我 agentic coding 时，让我随时知道它到底在推进 / 卡住 / 烧钱 / 乱改， 并且只在重要时刻、用恰当的方式提醒我——有用，且不烦。」
衡量成功的唯一问题：任意时刻能否 5 秒内答出「我所有正在跑的 Claude Code 现在分别什么状态？有谁需要我现在介入？」

我们依赖一个 Claude Code 未公开承诺的内部格式。这是整个平台最大的系统性风险，必须正视—— 也正因如此才有了 doctor 校验层。

三层架构脊柱 总览 · 概念层

三支柱 · Activity

活动支柱 · activity 深潜 · 代码层

平台从「token tracker」升级为「ops dashboard」的关键一步（M1）。它从 transcript 尾部推断每个主会话的状态—— 但克制到近乎苛刻：绝不伪造 PERMISSION_NEEDED / STUCK，拿不准就并列「长任务 / 等授权 / 会话已关闭」，格式漂移就判 UNKNOWN。
stateDiagram-v2 direction LR [*] --> UNKNOWN UNKNOWN : UNKNOWN · 读不懂/漂移 → 不发事件 WORKING : WORKING · 正在生成 PROCESSING : PROCESSING · 工具执行中 AWAITING_USER : AWAITING_USER · 回到等你（含 idle） AMBIGUOUS_PENDING : AMBIGUOUS_PENDING · 久未返回的诚实对冲 WORKING --> AWAITING_USER : 一轮任务完成 PROCESSING --> AWAITING_USER : 工具返回后收尾 WORKING --> PROCESSING : 发起工具调用 WORKING --> AMBIGUOUS_PENDING : 超 stuck 阈值仍无输出 PROCESSING --> AMBIGUOUS_PENDING : 超阈值 AMBIGUOUS_PENDING --> AWAITING_USER : 最终返回 AWAITING_USER --> WORKING : 你发新消息 UNKNOWN --> WORKING : 恢复（静默重播种·不补发）
五状态纯函数 classify_state(last_msg, now, cfg)，13 个单测钉死每个状态与诚实边界。

诚实纪律（本支柱的重点）

  • 时钟 = 末条消息 timestamp，不是文件 mtime（后者会把早停的会话误判为活跃）
  • 挂起只看尾部位置，不做 tool_use↔result 的 id 配对
  • 久未返回 → AMBIGUOUS_PENDING 并列三种可能，不说死
  • 读不懂 → UNKNOWN → 不发任何事件（误报比漏报更伤信任）

读取与配置

  • _read_tail：只读尾部 256KB，单条超窗回退至上限 4MB
  • snapshot()：全会话快照，2s TTL 缓存供并发/自动刷新共享同一帧
  • ActivityConfig：idle_after_s=600（仅排序）· stuck_after_s=120 · snapshot_ttl_s=2.0
  • M4.5 修：优先显示真实思考 💭（实测 thinking 块约 29% 末段非空），拿不到才回退叙述

import：activity → {discovery, project} —— 只依赖发现与项目身份，不碰 token 内核 / procmon（P4 成立）。

⚖
为什么这么克制？整座塔架在「可信推断」上。一次 PERMISSION_NEEDED 误报对信任的伤害 > 十次正确 Info。所以 M1 宁可「测不准就不说」——真正可靠的 permission 检测直到 M4 控制层拿到官方 hook 才补上。

只有这些键能进事件载荷，杜绝对话内容 / 命令行 / 路径 / 密钥进入事件与通知：

tool_name state_from state_to age_s idle_step unresolved state_label kind model branch scope pct

显式排除：last_text / title / current_step。

两层幂等

  • 源头：边沿触发 + 单调台阶（idle/stuck step 只增不减）
  • 总线：dedup_key LRU 窗口（持续条件 move_to_end 不老化 → 不重响）
  • UNKNOWN → 不发；从 UNKNOWN 恢复 → 静默重播种，不重放

P7 控制层守则 —— 五道护栏（全部满足才允许「下达指令」）

① allow-list
只做 permission 审批，单一入口 handle_permission()，其余一律拒
② 你显式触发
系统永不自动决定；超时 = defer（非决定）
③ 二次确认 + 鉴权
hook 用 query token；看板用 X-Control-Token 头（关掉 CSRF/本机伪造）· secrets.compare_digest
④ 全审计
每决定进 _audit（maxlen 200）+ 发 COMMAND_ISSUED 事件
⑤ 失败安全
够不到目标 → 明确报「做不到」，绝不伪装成功、绝不瞎试有副作用的动作
🎯
顺带补上 M1 的缺口：检测 permission 时发真实 PERMISSION_NEEDED 事件——这是 activity 当年「测不准就不发」留下的空位，如今由官方 hook 精确补齐。token 存 ~/.tokmon/control_token（24 字符 · 0600）。
🚫
nudge / 停止 = 有意不做：研究确认 hook 只能注入上下文、不能执行指令，没有干净 API → 按失败安全原则不靠脆弱方式硬来。激活需你手动加 hook JSON（含 token）并重启会话。import：control → {events, project}。

元 · Principles

原则与不变量 总览 · 宪章

这一页是整座塔的地基与护栏。两个北极星定方向，八条原则定优先级， 内核 I1–I6 与平台 P1–P7 定「不可破坏的边界」，非目标抵御功能蔓延。每加一个东西，先问北极星。
🧭
tokmon 北极星：让我对「用 Claude Code vibe coding 烧了多少 token / 等价多少钱」，从「完全没感觉」变成「随手可见、心里有数、能复盘」。
🛰
平台北极星：当 Claude Code 替我 agentic coding 时，让我随时知道它在推进/卡住/烧钱/乱改，并只在重要时刻、用恰当方式提醒我——有用，且不烦。

八条设计原则（冲突时上位优先）

1 · 真实优先

数字/状态/风险必须可被信任。宁可显示「未知」也不悄悄报错。误报会摧毁信任。

2 · 永不自动干预

三支柱永远纯只读。控制是单独一层，只在你显式下达、经审计时动手。

3 · 本地优先

默认一切在本机。通知是唯一外发能力，默认关、内容最小化。

4 · 渐进可降级

缺某数据源 → 那个支柱降级而非全局崩。单点异常不拖垮全局。

5 · 判断 ≠ 打扰

平台的灵魂：监控层判断「发生了什么」，通知层决定「该不该打扰」。

6 · 有用且不烦

默认静默。靠严重度 + 静默时段 + 去抖让重要浮上来、噪音沉下去。

7 · 支柱独立

token/进程/活动各有内核，互不污染。平台只在事件总线汇合。

8 · 小步进化

每个版本都能独立交付价值，且默认不打扰——先「有用且不烦」，再谈丰富。

平台不变量 P1–P7

  • P1 监控只读（不改文件/配置/行为，不自动点 permission）
  • P2 判断与打扰分离（监控层永不直接调通道）
  • P3 事件是唯一契约（不绕过读原始信号）
  • P4 支柱独立（内核互不 import，只在总线汇合）
  • P5 默认静默、默认不外发
  • P6 误报零容忍倾向（拿不准就降级/不发）
  • P7 控制层守则（allow-list + 显式 + 鉴权 + 审计 + 失败安全）

非目标（抵御蔓延）

  • ❌ 不自动干预 coding（永不自动批/改/kill）
  • ❌ 不什么都通知（噪音通知是负价值）
  • ❌ 不默认外发敏感内容（命令行/代码/diff/路径）
  • ❌ 不 hook / 不拦截 Claude Code（只读 transcript + 看进程）
  • ❌ 不做账单对账（算等价用量价值，非真实账单）
  • ❌ 不做团队 SaaS / 多租户（给「我自己」的本地工具）
🎁
一句话给未来的自己：别把它做成一个炫的 dashboard 集合。它在替我跑的时候，让我知道它在推进/卡住/烧钱/乱改， 并且只在重要时刻、用恰当方式提醒我，其余时候安静。每加一个东西，先问：这让那件事更清楚、或那次打扰更精准了吗？不是，就先别加。
